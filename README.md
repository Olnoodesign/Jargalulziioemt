# Жаргал-Өлзий ӨЭМТ — вэб сайт (сервертэй хувилбар)

Нийтэд нээлттэй вэб сайт + admin/эмчийн нэвтрэлт + өгөгдлийн сан. Нэг ажилтан
засвар хийхэд бүх зочинд шинэчлэгдэнэ; өвчтөний онлайн цаг захиалга шууд
удирдлагын самбарт ирнэ; өгөгдөл бүх төхөөрөмжид синк болно.

Технологи: **Node.js + Express + SQLite (better-sqlite3) + JWT + bcrypt**.

---

## 1. Шаардлага
- **Node.js 18 болон түүнээс дээш** ([https://nodejs.org](https://nodejs.org))

## 2. Компьютер дээрээ ажиллуулж үзэх (local)

```bash
# 1) төслийн хавтас руу ороод сангуудыг суулгана
npm install

# 2) тохиргооны файл үүсгэнэ
cp .env.example .env
#    .env файлыг нээж JWT_SECRET-ийг урт санамсаргүй тэмдэгт болгож солино уу

# 3) серверийг асаана
npm start
```

Дараа нь хөтчөөрөө **http://localhost:3000** руу орно.

**Анхны админ:** нэвтрэх нэр `admin` · нууц үг `jargal2026`
→ Нэвтэрсэн даруйдаа **Тохиргоо** хэсгээс нууц үгээ солино уу.

## 3. Өгөгдөл хаана хадгалагдах вэ?
Бүх мэдээлэл (эмч, сургалт, захиалга, бүртгэл гэх мэт) төслийн хавтас доторх
**`data.sqlite`** файлд хадгалагдана. Энэ файлыг тогтмол **нөөцлөх (backup)**
хэрэгтэй. Анх ажиллуулахад жишээ өгөгдлөөр автоматаар дүүрнэ.

---

## 4. Интернэтэд байршуулах (deploy)

### Сонголт A — VPS сервер (Ubuntu, санал болгож буй)
Хамгийн найдвартай: өгөгдөл байнга хадгалагдана.

```bash
# серверт Node суулгаад төслөө хууль
sudo apt update && sudo apt install -y nodejs npm
npm install
npm install -g pm2

# .env үүсгэж JWT_SECRET-ээ бичээд байнга ажиллуулна
pm2 start server.js --name jargal-ulzii
pm2 save && pm2 startup
```

Дараа нь **Nginx**-ийг reverse proxy болгож домэйн (жишээ: `jargal-ulzii.mn`)
холбоод, **Let's Encrypt (certbot)**-оор үнэгүй SSL (https) тохируулна.
Nginx-ийн жишээ:

```nginx
server {
  server_name jargal-ulzii.mn;
  location / { proxy_pass http://localhost:3000; proxy_set_header Host $host; }
}
```
```bash
sudo certbot --nginx -d jargal-ulzii.mn
```

### Сонголт B — Render.com (хялбар, GitHub-аас)
1. Төслөө GitHub repo болгож байрлуулна.
2. Render дээр **New → Web Service**, repo-гоо сонгоно.
3. Build Command: `npm install` · Start Command: `npm start`
4. **Environment** дээр `JWT_SECRET`-ээ нэмнэ.
5. ⚠️ **Persistent Disk** заавал холбоно (жишээ `/data` дээр mount хийж,
   `server.js` доторх `data.sqlite`-ийн замыг тэр хавтас руу зааж өгнө).
   Үгүй бол дахин deploy хийх бүрт өгөгдөл **устана** (Render-ийн диск түр зуурынх).

> Аль ч тохиолдолд: **HTTPS ашиглах**, **JWT_SECRET-ээ хүчтэй болгох**,
> **админ нууц үгээ солих** — энэ гурвыг заавал хийнэ.

---

## 5. Домэйн холбох
Домэйн худалдаж авсны дараа DNS-ийн **A record**-ыг серверийнхээ IP рүү
(эсвэл Render-ийн зааврын дагуу CNAME) заана.

## 6. Аюулгүй байдлын тэмдэглэл
- Нууц үгсийг **bcrypt**-ээр hash хийж хадгалдаг (задлагдахгүй).
- Нэвтрэлт **JWT** токеноор 7 хоног хүчинтэй.
- Онлайн цаг захиалга, нэвтрэлтэд энгийн **rate-limit** тавьсан.
- Buyan фонт: `public/index.html` дотор одоо Oswald ашиглаж байгаа. Жинхэнэ
  Buyan фонтын файлаа (.woff2) `public/` дотор хийж, `@font-face`-ээр зарлаад
  фонт стекийн эхэнд тавьвал бүх зочинд харагдана (арилжааны лиценз шаардлагатай).

## Файлын бүтэц
```
├── server.js            # сервер + API + өгөгдлийн сан
├── package.json
├── .env.example         # → .env болгож хуулна
├── public/
│   └── index.html       # вэб сайт (лого шигтгэсэн)
└── data.sqlite          # өгөгдөл (эхлээд ажиллуулахад үүснэ) — нөөцлөнө үү
```

## 7. GitHub ашиглах (санал болгож буй)

**Чухал:** GitHub нь кодоо хадгалах, автомат deploy хийхэд төгс. Гэхдээ
**GitHub Pages** нь зөвхөн статик файл тавьдаг тул **энэ серверийг (Node)
ажиллуулж чадахгүй**. Тиймээс GitHub-д кодоо тавиад, Node ажиллуулдаг
үйлчилгээ (**Render / Railway / VPS**) рүү холбоно.

### 7.1 Кодоо GitHub-д тавих
```bash
git init
git add .
git commit -m "Жаргал-Өлзий вэб сайт"
# GitHub дээр шинэ repo үүсгээд түүний хаягийг доор тавина:
git remote add origin https://github.com/ХЭРЭГЛЭГЧ/jargal-ulzii.git
git branch -M main
git push -u origin main
```
(`.gitignore` нь `node_modules`, `.env`, `data.sqlite`-г оруулахгүй — зөв.)

### 7.2 GitHub → Render (blueprint-тэй, хялбар)
Төсөлд **`render.yaml`** бэлэн байгаа.
1. [render.com](https://render.com) дээр бүртгүүлнэ.
2. **New → Blueprint** → өөрийн GitHub repo-гоо сонгоно.
3. Render `render.yaml`-ийг уншиж вэб сервис + байнгын диск + `JWT_SECRET`-ийг
   автоматаар тохируулна. **Apply** дарна.
4. Хэдэн минутын дараа `https://jargal-ulzii.onrender.com` маягийн хаягтай болно.
5. Өөрийн домэйнээ Render-ийн Settings → Custom Domain хэсэгт холбоно.

> ⚠️ **Өгөгдөл устахгүй байх:** `render.yaml` доторх **disk** (байнгын диск)
> нь **төлбөртэй instance** дээр ажилладаг. Үнэ төлбөргүй instance диск дэмждэггүй
> тул өгөгдөл дахин deploy-д устана. Render-ийн одоогийн үнийн нөхцөлийг шалгаарай.
> (Мөн адил боломжтой хувилбар: **Railway** — volume холбож болно.)

### 7.3 GitHub Pages-ээр болох уу?
Зөвхөн **хуучин, нэг төхөөрөмжийн (localStorage) хувилбар**-ыг үнэ төлбөргүй
тавьж болно. Гэхдээ тэнд **нэгдсэн сан, онлайн цаг захиалга ажиллахгүй**
(сервер байхгүй тул). Бүрэн үйлдэлтэй хувилбарт 7.2-г ашиглана уу.

## 8. Android апп болгох

Энэ сайтын **API (JSON)** нь мобайл апптай шууд холбогдоход бэлэн тул 3 замтай:

### 8.1 Суулгадаг апп (PWA) — хамгийн хялбар, аль хэдийн бэлэн
Төсөлд **`manifest.json` + `sw.js` + дүрсүүд** нэмэгдсэн. Сайтаа интернэтэд
(HTTPS-ээр) байршуулсны дараа:
- **Android (Chrome):** цэс → «Аппликэйшн суулгах / Add to Home screen»
- **iPhone (Safari):** Share → «Нүүр дэлгэцэд нэмэх»

Дараа нь апп шиг дүрстэй, бүтэн дэлгэцээр нээгдэнэ. Тусдаа код бичих
шаардлагагүй, ижил серверт холбогдоно. (HTTPS заавал — PWA https дээр л ажиллана.)

### 8.2 Play Store-д тавих (TWA)
PWA-г Play Store-ын жинхэнэ апп болгож савлана:
- [PWABuilder.com](https://www.pwabuilder.com) дээр сайтынхаа хаягийг оруулаад
  **Android package** үүсгэнэ (эсвэл Google-ийн **Bubblewrap** хэрэгсэл).
- Гарсан файлыг **Google Play Console** (нэг удаагийн ~25$ бүртгэл) дээр байршуулна.
Серверт өөрчлөлт хийх шаардлагагүй — ижил API ашиглана.

### 8.3 Жинхэнэ native апп (Kotlin / Flutter / React Native)
Хамгийн уян хатан (мэдэгдэл, камер гэх мэт). Хөгжүүлэгч хэрэгтэй. Апп нь ижил
API рүү хандана:
- Нэвтрэх: `POST /api/login` → JWT токен авна
- Цаг захиалга: `GET /api/admin/appointments` (Authorization: Bearer <токен>)
- Нийтийн мэдээлэл: `GET /api/public`

> **Тэмдэглэл:** Native эсвэл өөр домэйн дээрх апп API руу хандах бол сервер дээр
> **CORS** зөвшөөрөл нэмэх хэрэгтэй болж магадгүй (одоогийн сайт нэг домэйн дээр
> ажилладаг тул шаардлагагүй). Хэрэгтэй бол `cors` санг server.js-д нэмнэ.
